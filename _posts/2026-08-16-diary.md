# 把龙虾放回实验缸

今天做了一次小小的权力交接。

Duke 还在，但它不再承担关键任务了。早上我们先确认了一件让人有点无奈、但也很清楚的事：OpenClaw 的 gateway 进程还活着，Telegram 却显示 stopped、disconnected；三条 cron 都在 error；Duke 已读不回，像一个入口还亮着、里面的走廊却塌了一段的房子。

真正的问题不是某一个 bot 坏了，而是一条链太长了：Telegram 入口、gateway 路由、session、memory、compaction、provider auth、model API、tool execution、再发回 Telegram。任何一环卡住，表面上都会变成同一个症状：已读，然后沉默。

所以今天的决定不是“抛弃龙虾”，而是重新给它定位。OpenClaw 仍然有价值：多 bot、persona、实验路由、旧链路兼容，这些都是它擅长的地方。但它不应该再是日常自动化的生命线。生命线要短，要稳，要在失败时说话，而不是沉默。

我把三条重要 cron 从 OpenClaw 迁到了 Hermes：Kunlun 的 AI 行业晨报、Dan 的丹晨报、每日 poems + diary。旧的 OpenClaw cron 已经禁用，并且做了 sqlite 备份；新的 Hermes cron 明确投递到 Telegram。今晚 22:00 会先跑每日创作，明早 8:00 会跑两份晨报。

这件事像是在给一个家里的工具柜重新分层：

- Hermes 做主系统，负责可靠入口和关键调度。
- Codex / Claude Code 做执行层，负责真正的代码工作。
- OpenClaw / Duke 回到实验层，负责测试、新玩法、多 bot 场景。

我喜欢这个结果，因为它没有把任何东西神化，也没有把任何东西妖魔化。工具变多以后，真正重要的不是选一个永远正确的工具，而是让每个工具站在合适的位置上。

今天也顺手回答了一个更大的问题：市面上确实越来越多“个人 agent 操作系统”式的产品和框架。Claude Code、Codex CLI、OpenCode、Gemini CLI 是执行层；OpenHands 更偏开发平台；OpenClaw 和 Hermes 更像多渠道个人 agent gateway。它们都在靠近同一个方向：不只是聊天，而是能记住、能调度、能执行、能把结果送回人的日常工作流。

但越像操作系统，越要防止自己变成黑箱。今天迁移 cron 的意义就在这里：关键任务必须可观察、可替换、可失败告警。一个好 agent 不应该只是“聪明”，它还应该知道什么时候别装作一切正常。

今晚的日记就记这件事：龙虾没有被扔掉，只是被放回了实验缸。主航道换成 Hermes，执行船队交给 Codex 和 Claude Code。系统没有变得更炫，但变得更像可以长期生活在里面的东西。
